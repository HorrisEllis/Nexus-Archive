## Confirmed findings, checked by hand

### cockpit is live — and has a route that throws on every call

`guardian/server.js:2046` — `GET /forge/health` does
`require('../cockpit/forge')`. **There is no `cockpit/forge.js`.** The folder
holds cli.js, core.js, live.js, pipeline.js, cockpit.spec. Verified by resolving
it: `MODULE_NOT_FOUND`. The route is registered and 500s every time it is hit.

So cockpit is not unused, which was the working assumption:

- `cockpit/cli.js` — **live**. `lib/agent-tools/tools/execution/run-command.js`
  imports `INTERACTION_CONTRACT` from it. A real agent tool depends on it.
- `cockpit/pipeline.js` (992 lines), `cockpit/live.js` — reachable.
- `cockpit/core.js` — orphaned.
- `cockpit/forge.js` — **referenced and absent.**

### Two of the five contract surfaces are dead code

Directly relevant to the contract-hub question:

- `contracts/SYSTEM-CONTRACTS.js` — **1,099 lines, orphaned.**
- `seams/seam-contracts.js` — **orphaned**, and it declares `PORTS` as
  "single source of truth" while 10+ other files declare ports independently.
- Live: `contracts/nexus-interaction-contract.js`, `lib/seam/build-contract.js`,
  gap-field's repair contracts.

A hub over five surfaces is really a hub over three, plus a decision about
whether the other two are dead or merely unwired. That is a much smaller build
than it looked yesterday.

## How to use this

Do not mass-delete. Three of these are already known to be real work that was
simply never wired (`chunk-build-orchestrator`, `emerge/chunk`, `tool-index`'s
feeders). The value is triage: for each concentration, decide **wire it, archive
it (§0.3, never delete), or accept it as reached-dynamically** — and record which.
