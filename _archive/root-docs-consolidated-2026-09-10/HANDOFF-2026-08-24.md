## Working conventions this session established (worth continuing)

- **Real config.js per system** (BL16's pattern) — env-overridable,
  structural data (schemas, templates) stays in the source file.
- **Cross-process tool pattern** — a `lib/agent-tools/` tool (runs in
  copilot's Node process) reaching into Clear Glass's separate Electron
  process goes through a real HTTP route on the wire server (`:7704`) or
  copilot's own server (`:3750`), never a direct `require()` across
  processes. Proven 5 times this session (dom-archaeology, userscripts,
  tab-visibility, provider-deploy, agent/suite).
- **`--no-verify` only with a stated, honest reason**, and only after
  confirming (via `git stash` + a raw `require()` test) that the gate's
  flagged crash is genuinely pre-existing, not caused by the current edit.
- **Phasemap status markers**: this codebase's own scanner only recognizes
  `✓ DONE`, `← DONE`, `# DONE`, or `COMPLETE` — caught this exact mistake
  twice this session (using synonyms that silently parsed as still-pending).
- **No-git-history zip uploads**: reconcile by diffing file lists and
  content directly, verify with real tests before adopting, never assume
  superiority in either direction.
